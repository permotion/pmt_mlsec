## Hypothesis

The baseline has ~1,886 FPs. To improve Precision we need to understand what those FPs have in common — what makes them "suspicious" to the model even though they are legitimate requests. If we find the pattern, we can add features that break it.

---

## Considered options

| Option | Why not |
|---|---|
| Test more algorithms | The ~0.94 ROC-AUC ceiling is the same in all of them — the problem is not the algorithm |
| Move to Model B | Leaves the root cause misunderstood |
| Add MLflow first | Useful for organizing, but doesn't solve the underlying problem |
| **Feature importance + FP analysis** ← chosen | Addresses the root cause |

## Notebook sections

1. Re-train base RF (15 features) as reference
2. Feature importance — contribution ranking of each feature
3. Compare FP vs TN — what do false positives have in common?
4. Evaluate 4 candidate features and measure correlation with the label
5. Extended RF (19 features) vs base RF — measured impact

## Findings

### False positives analysis — the central finding

The 1,886 FPs **do not have any payload indicator**:

| Feature | FP | TN | Interpretation |
|---|---|---|---|
| `url_length` | **larger** | smaller | FPs have longer URLs |
| `content_length` | **larger** | smaller | FPs have longer bodies |
| all `url_has_*` | ~0.000 | ~0.000 | No attack indicators in URL |
| all `content_has_*` | ~0.000 | ~0.000 | No attack indicators in content |

The model classifies as an attack solely because the URL or body is longer. It learned "long URL = suspicious", without distinguishing between a long URL with attack payload and a long URL with legitimate content.

### Candidate features correlation

| Feature | Correlation | Decision |
|---|---|---|
| `url_pct_density` | **0.267** | ✅ — gives context to length |
| `url_param_count` | **0.146** | ✅ — gives context to length |
| `url_has_traversal` | NaN | ❌ — `../` never appears literal, always encoded as `%2F` |
| `post_has_pct27` | NaN | ❌ — insufficient intersection |

`url_pct_density` gives exactly the missing context: a long URL with high encoding density (`%27`, `%3C`) is very different from a long URL with normal text.

### Measured impact

| Model | ROC-AUC | Recall | Precision |
|---|---|---|---|
| Base RF (15 features) | 0.939 | 0.951 ✅ | 0.655 ❌ |
| Extended RF (17 features) | **0.950** | 0.951 ✅ | **0.704** ❌ |

**+0.049 Precision** with only 2 new features — validated signal.

---

## Decision

Add `url_pct_density` and `url_param_count` to the official preprocessing. Create `preprocess_csic_v2.py` and re-train all 4 complete models.
