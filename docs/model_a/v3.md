## Hypothesis

The same reasoning that led from v1 to v2 applies to POST content: `content_length` alone does not distinguish between a long body with a payload and one without it. `content_pct_density` (ratio of encoded chars in the body) should give that context.

---

## Pre-training analysis

### Correlation in POST subpopulation

Analyzing **only the 17,580 POST requests** (where content has real meaning, unlike GETs whose content is always empty):

| Feature | Correlation with label (POST only) |
|---|---|
| `content_pct_density` | **0.406** |
| `content_has_pct27` | 0.264 |
| `content_has_dashdash` | 0.214 |
| `content_has_script` | 0.182 |
| `content_has_pct3c` | 0.179 |
| `content_length` | 0.149 |
| `content_param_count` | 0.062 |

`content_pct_density` has 0.406 correlation in POSTs — stronger than `url_pct_density` (0.267) which already improved Precision +0.049.

### v2 model FP distribution

| Type | Amount | % |
|---|---|---|
| FP GET | 935 | 62.2% |
| FP POST | 569 | 37.8% |

**62.2% of FPs are GETs** — they have no content, so content features cannot attack them. The theoretical ceiling of this strategy is reducing 569 POST FPs.

### POST FPs — same pattern as GET FPs

| Feature | FP POST | TN POST |
|---|---|---|
| `content_length` | 63,270 | 4,304 |
| `content_has_pct27` | 0.005 | 0.000 |
| `content_has_*` (rest) | ~0.000 | ~0.000 |

POST FPs also have no payload indicators — they only have longer bodies.

## Evaluated features

| Feature | Global correlation | POST only correlation | Decision |
|---|---|---|---|
| `content_pct_density` | 0.279 | **0.406** | ✅ add |
| `content_param_count` | 0.157 | 0.062 | ❌ weak signal in POSTs |

`content_param_count` has 0.157 global correlation but only 0.062 in POSTs — global correlation is inflated by the GET/POST structure (GETs have 0 params and are more frequently normal). Discarded.

## Feature importance

Plots were logged as artifacts in MLflow. Relevant findings:

- **RF:** `url_length` still dominates (0.46). `content_pct_density` is 3rd feature (0.12) — it's used, but doesn't displace `url_length`.
- **XGBoost:** `url_param_count` (0.22) and `content_param_count` (0.17) up top — despite low linear correlation, XGBoost finds non-linear relationships.
- **LightGBM:** top 4 are `url_length`, `content_length`, `content_pct_density`, `url_pct_density`.

---

## Analysis

`content_pct_density` provided real signal and consistent improvement, but much lower than expected:
- RF reduced FPs from 1,504 → 1,416 (-88), we expected -569
- Most POST FPs have no encoding in the body — they are just longer. The same structural problem as with URL

**62.2% of FPs are GETs** and are not attackable with content features. To close the remaining gap (0.713 → 0.85 = 0.137) we must attack those 935 GET FPs.

---

## Decision

Create `csic2010_feature_analysis_v4.ipynb` analyzing **URL structure in the GET subpopulation**:

- `url_path_depth` — number of `/` in the path
- `url_query_length` — length of query string (after `?`)
- `url_has_query` — presence of `?`

These features contextualize `url_length` differently than `url_pct_density` — they separate path length from parameter length.
